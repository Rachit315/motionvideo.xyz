# Contributing to MotionVideo

Thanks for your interest in contributing! This guide covers everything you need to get the repo running locally and land a change.

## Prerequisites

- **Node.js** — `^20.19.0 || >=22.12.0` (see `engines` in [`package.json`](./package.json))
- **pnpm** — version pinned in [`package.json`](./package.json)

## Getting started

```bash
git clone https://github.com/motionvideohq/motionvideo.xyz.git
cd motionvideo.xyz
pnpm install
cp apps/web/.env.example apps/web/.env
pnpm --filter @motionvideo/web db:migrate:local
pnpm dev
```

The site runs at [http://localhost:3000](http://localhost:3000). `pnpm install` also installs the [Lefthook](https://github.com/evilmartians/lefthook) pre-commit hook.

### Environment variables

`.env` is gitignored. Copy it from `apps/web/.env.example` and never commit real secrets.

Most integrations are optional in development:

- An empty `RESEND_API_KEY` prints emails to the dev server console.
- Empty payment, Turnstile, Google, and PostHog keys disable those features.
- `apps/web/wrangler.jsonc` holds the non-secret production defaults; `.env` overrides them locally.

Production secrets are set with `pnpm --filter @motionvideo/web exec wrangler secret put <NAME>` and are not needed for local development.

### Local database

The local D1 database is created from the migrations in `apps/web/drizzle`:

```bash
pnpm --filter @motionvideo/web db:migrate:local
```

When you change a Drizzle schema, generate a migration and apply it:

```bash
pnpm --filter @motionvideo/web db:generate
pnpm --filter @motionvideo/web db:migrate:local
```

`apps/web/src/server/db/schema.ts` is generated by the Better Auth CLI, not hand-written. Regenerate it with:

```bash
pnpm --filter @motionvideo/web auth:schema
```

Local Cloudflare bindings (D1, R2, Durable Objects, rate limiters) are emulated by the Cloudflare Vite plugin, so `pnpm dev` does not need a Cloudflare account. Wrangler stores local state in `apps/web/.wrangler`, which is gitignored.

## Development

### Project layout

| Path | What it is |
| --- | --- |
| `apps/web` | The MotionVideo site: TanStack Start on Cloudflare Workers, with D1, R2, and Durable Objects |
| `apps/videos` | Remotion project for the launch and promo videos |
| `docs` | Internal planning notes and migration docs |

### Commands

| Command | What it does |
| --- | --- |
| `pnpm dev` | Start the site on port 3000 |
| `pnpm build` | Production build of the site |
| `pnpm typecheck` | `wrangler types` + `tsc --noEmit` for both workspaces |
| `pnpm check` | Lint and format check (Ultracite) |
| `pnpm fix` | Auto-fix lint and format issues |
| `pnpm studio` | Open the Remotion project in Remotion Studio |
| `pnpm --filter @motionvideo/web email:dev` | Preview React Email templates on port 3001 |
| `pnpm deploy` | Build, migrate the remote D1 database, and deploy with Wrangler |

`pnpm deploy` and the remote database commands touch production Cloudflare resources. Maintainers run them; contributors should not need them. GitHub Actions only runs checks; it does not deploy.

### Email templates

React Email components live in `apps/web/src/emails`. Preview them with:

```bash
pnpm --filter @motionvideo/web email:dev
```

The preview server runs on port 3001.

### Remotion videos

The videos in `apps/videos` render with Remotion. Open the project in Remotion Studio:

```bash
pnpm studio
```

If Studio fails because the licensed Timeless font is missing, pull the website font first:

```bash
pnpm --filter @motionvideo/web fonts:pull
```

The video commands are separate from the website build.

## Checks

```bash
pnpm check      # lint and format check (Ultracite)
pnpm fix        # auto-fix lint and format issues
pnpm typecheck  # wrangler types + tsc --noEmit, both packages
pnpm build      # production build
```

`pnpm typecheck` expects `apps/web/.env` to exist because `wrangler types` reads secret names from it. It also regenerates `apps/web/worker-configuration.d.ts`, which is gitignored. Run `pnpm build` when your change touches routing, prerendering, or Cloudflare bindings.

There is no automated test suite yet. CI runs `pnpm check`, `pnpm typecheck`, and `pnpm build`; include the commands you ran and a short manual verification path in your pull request.

A pre-commit hook via [Lefthook](https://github.com/evilmartians/lefthook) runs `pnpm fix` on staged files.

## Generated files

Change their source instead of editing these by hand:

- `apps/web/src/server/db/schema.ts` — Better Auth CLI output. Regenerate with `pnpm --filter @motionvideo/web auth:schema`.
- `apps/web/drizzle/**` — Drizzle migrations. Create with `pnpm --filter @motionvideo/web db:generate` and apply with `db:migrate:local`.
- `apps/web/src/routeTree.gen.ts` — TanStack Router output, regenerated by `pnpm dev` and `pnpm build`.
- `apps/web/worker-configuration.d.ts` — Wrangler types, regenerated by `pnpm typecheck` or `pnpm --filter @motionvideo/web cf-typegen`.

## Fonts and media

Media and large assets live in R2 (`motionvideo-assets`) rather than the repository.

The licensed Timeless font is pulled into a gitignored directory by `predev` and `prebuild`. If the download fails, place the licensed file at `apps/web/public/fonts/timeless/` or set `FONT_SRC=<path-or-url>` for the pull.

## Before opening a pull request

Every pull request must be tied to an issue. Before opening a PR, search the existing issues and pull requests so you do not duplicate active work. If there is no existing issue, open one with the relevant template and describe the problem, use case, or bug reproduction.

For non-trivial changes, wait for discussion on the issue before investing in the implementation. The goal is to agree that the problem is real and that the proposed direction fits MotionVideo before review shifts to code.

To avoid PRs that are unlikely to be reviewed or merged:

- Do not send broad rewrites, style-only churn, or formatting-only changes unless a maintainer asked for them.
- Do not bundle unrelated fixes or refactors into one PR. Split them so each PR has one reviewable purpose.
- Do not change public behavior based only on a hypothetical use case. Include a concrete user story, reproduction, or example that shows the need.
- Do not claim an issue silently. Comment before starting work, and check the thread in case someone else is already working on it.

## Submitting a pull request

1. Fork the repo and create a branch from `main`.
2. Link the issue where the change was discussed and agreed on.
3. Make your change, including documentation where relevant.
4. Sign off every commit with `git commit -s`.
5. Make sure `pnpm check`, `pnpm typecheck`, and `pnpm build` pass.
6. Open the PR with a clear description of the problem and solution. Include screenshots or a short recording for visible UI changes.

## Developer Certificate of Origin (DCO)

All contributions are made under the [Developer Certificate of Origin](https://developercertificate.org/). Every commit must include a `Signed-off-by` line matching the commit author's name and email:

```text
Signed-off-by: Jane Doe <jane.doe@example.com>
```

Add it automatically with:

```bash
git commit -s -m "your commit message"
```

If you forget, amend the last commit:

```bash
git commit --amend -s --no-edit
```

To sign off a series of commits, rebase with `--signoff`:

```bash
git rebase --signoff main
```
